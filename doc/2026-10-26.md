## 1. 왜 이걸 배우는가?

### Q1. 보안 담당자는 왜 리눅스를 쓰는가?
> **A1.** 기업의 핵심 서버와 클라우드 인프라 대다수가 리눅스로 운영되며, 침해사고 대응과 보안 분석을 수행하기 가장 빠르고 정확한 환경이기 때문이다.

* **운영환경의 현실**
  * 실제 기업의 운영 서버와 클라우드 인스턴스는 자원 절약과 보안성을 위해 GUI 없이 CLI 환경으로만 배포된다.
  * 따라서 원격 접속(SSH) 후 명령어로 제어할 수밖에 없다.
* **신속한 침해사고 대응**
  * 공격자가 침투했을 때 열려 있는 포트(`ss`), 실행 중인 악성 프로세스(`ps`), 변조된 시스템 파일(`find`, `/proc` 디렉토리)을 즉각 확인하고 격리·차단할 수 있다.
* **대용량 로그 초고속 분석**
  * 수십 기가바이트(GB)에 달하는 방대한 접속·보안 로그를 무거운 뷰어 없이 `grep`, `awk`, `sed` 등의 파이프라인 명령어로 수 초 만에 필터링해 이상 징후를 추적한다.
* **보안 점검 자동화**
  * 반복되는 취약점 스캔, 계정 무결성 검증, 접근 통제 정책 적용 등을 쉘 스크립트(Bash)로 작성해 자동으로 수행할 수 있다.
* **보안 도구 표준 환경**
  * 네트워크 패킷 캡처(`tcpdump`), 포트 스캔(`nmap`), 디지털 포렌식 및 침투 테스트 도구 등 업계 표준 보안 도구 대부분이 리눅스 CLI 기반으로 개발되어 동작한다.

### Q2. 개발자와 보안 담당자는 왜 깃허브에 코드를 올릴까요?
> **A2.** 단순한 코드 저장을 넘어, 버전 관리(형상 관리), 협업과 코드 리뷰, 그리고 보안 자동화를 단일 플랫폼에서 체계적으로 수행하기 위해서이다.

#### 🔹 개발자 관점
* **버전 관리 및 추적:** Git 기반으로 코드 변경 이력을 세밀하게 기록하여, 오류 발생 시 특정 시점으로 즉각 롤백하거나 브랜치를 분기해 안전하게 기능을 추가한다.
* **효율적인 협업:** Pull Request(PR) 기능을 통해 팀원 간 코드 리뷰를 하고 병합하며 코드 품질을 유지한다.
* **오픈소스 기여 및 포트폴리오:** 전 세계 오픈소스 생태계에 참여하고, 본인의 개발 역량과 프로젝트 결과물을 투명하게 증명한다.

#### 🔹 보안 담당자 관점
* **보안 검사 자동화:** GitHub Actions 등을 활용해 코드가 배포되기 전 SAST(정적 코드 보안 분석), 의존성 패키지 취약점 점검, 컨테이너 보안 검사를 CI/CD 파이프라인에 통합한다.
* **비밀값 유출 방지:** API 키, 데이터베이스 패스워드, SSH 키 등이 실수로 커밋될 경우 이를 감지해 알림을 주거나 푸시 자체를 차단한다.
* **보안 취약점 제보 및 패치 관리:** 보안 권고 기능을 통해 발견된 취약점을 비공개로 제보받고, 보안 패치를 협업하여 신속하게 배포한다.
* **보안 정책 및 룰셋 공유:** 조직 내 보안 정책, 침해사고 대응용 룰, 보안 점검 쉘 스크립트를 중앙에서 버전 관리하며 표준화한다.

#### 💡 공통 핵심 가치
* **"Shift-Left" 보안 구현:** 개발 초기 단계부터 보안 도구와 감사를 코드 저장소에 직접 결합하여, 서비스 출시 이후 발생할 수 있는 보안 사고 위험과 수정 비용을 획기적으로 낮출 수 있다.

## 2. 이 말이 무슨 뜻인가?

### Q1. 터미널은 무엇을 하는 프로그램인가요?
> **A1.** 사용자가 키보드로 명령어를 직접 입력해 운영체제를 제어하고 작업을 지시하는 텍스트 기반 대화 창이다.

마우스로 폴더를 더블클릭하고 아이콘을 눌러 프로그램을 여는 GUI 방식과 달리, 텍스트 명령어를 통해 파일 탐색, 프로그램 실행, 서버 관리, 빌드 및 배포 등의 작업을 빠르고 정밀하게 수행한다.

---

### Q2. 경로(Path)는 무엇을 나타내는 글자인가요?
> **A2.** 컴퓨터 파일 시스템 안에서 특정 파일이나 폴더가 위치한 고유한 주소를 나타내는 문자열이다.

시작 지점에 따라 시스템 최상위 루트부터 시작하는 **절대경로**와, 현재 작업 중인 폴더 위치를 기준으로 표기하는 **상대경로**로 나뉜다.

---

### Q3. 깃배시(Git Bash)는 윈도우에서 왜 따로 필요한가요?
> **A3.** 윈도우 운영체제 안에서도 리눅스/유닉스 표준 쉘(Bash) 환경과 리눅스 명령어를 그대로 사용하기 위해 필요하다.

* 윈도우 기본 터미널(CMD, PowerShell)은 리눅스와 명령어 문법 및 동작 방식이 다르다.
* Git 도구와 대다수 오픈소스 개발·배포 가이드, 서버 인프라 스크립트는 리눅스 Bash 문법이 표준이다.
* Git Bash를 사용하면 윈도우에서도 별도의 가상머신 없이 `ls`, `grep`, `cat`, `ssh` 등 익숙한 리눅스 명령어로 Git을 다루고 개발 작업을 동일하게 진행할 수 있다.

## 5. Git Bash 주요 명령어

| 명령어 | 설명 |
| :--- | :--- |
| `pwd` | 지금 위치한 폴더의 경로를 출력 |
| `ls` | 폴더 안의 목록을 출력 |
| `ls -a` | 이름이 점(`.`)으로 시작하는 숨김 항목까지 함께 출력 |
| `cd "경로"` | 작업 디렉토리 경로 이동/설정 |
